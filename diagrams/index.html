架构图集

Claude Chat Mobile 按功能域拆开的 13 张可交互图。每张都是自包含 HTML：支持明暗主题、平移缩放、搜索聚焦、关系追踪与导出，无需联网或任何依赖。图中事实取自代码与 docs/architecture.md，不是示意。

全局

先看这张，再按需要下钻。

00architecture
系统总览

Web 驾驶与 CLI 驾驶两条数据路径，以及它们共享的 transcript 与控制面。

  • Web 走 Agent SDK 双向流；CLI 驾驶不经过 SDK
  • 同一时刻只允许一个驾驶员写入

双通道与同步

改这几处前务必先读——凭直觉改基本会错。

01sequence
Web 驾驶：一条消息的完整时序

从 user:message 到 agent:event 回流，含幂等闸与实例置换。

  • 去重 ID 只在 send 已 resolve 后才登记
  • 三种负 ack 各自对应不同的客户端行为
02sequence
CLI 驾驶：只读镜像的建立与解锁

磁盘轮询追平、hooks 即时信号，以及静默判定后的锁释放。

  • 常态 2.5s 轮询，进镜像后收紧到 1s
  • hooks 只是加速触发器，transcript 才是真相源
03lifecycle
单驾驶员模型：镜像锁状态迁移

五条默认规则、防自锁的那条判定，以及有意保留的逃生口。

  • 只认终端写的未完结尾部，己方 sdk-ts 撑不住锁
  • 解锁只撤 Web 侧的锁，不会停止终端进程
08sequence
事件信封与断线回放

seq 去重、epoch 世代，以及超出环形缓冲后的两级回退。

  • 缓冲有界，缺口过大就回退鉴权的 session:history
  • 事件 type 是闭合集合，双向契约硬闸校验

安全与边界

失败方向是逐条选过的，不是「所有异常都拒绝」。

04workflow
鉴权与范围边界：六道门

从 AUTH_TOKEN 到工具审批，逐层收窄且互不替代。

  • 限速措辞按来源分档，本机来源绝不说成暴力尝试
  • fail-closed 有两个刻意的例外
05lifecycle
工具审批的生命周期与终态

pending / approved / denied / expired，以及留存治理。

  • 重启后遗留 pending 一律标 expired
  • 批一个已无执行上下文的操作是危险假象
06workflow
离线唤醒：按可见性分档的推送抑制

哪些无条件推、哪一类才抑制，以及正文最小化。

  • 前台判据是 client:presence，不是 socket 连着
  • result（及网关静默告警）按前台抑制

域地图

按后端分层与前端模块边界组织。

07dataflow
文件域：四段闸门

浏览、预览、搜索、写入、git 变更与附件通道。

  • 附件落数据目录，不写进用户项目
  • symlink 判据是「父目录用户可写」
09architecture
运维与可观测

配置事实源、启动自检、受管服务、审计与告警。

  • 配置读写必须同源，写错源等于假成功
  • 面板判定化，不展示裸计数器
10dataflow
会话域：三条互不混判的聚合链

会话列表、「需要你」待办、跨设备未读位点。

  • 服务告警绝不进「需要你」那个数字
  • 未读位点在服务端合并，manual 胜过 seen
11architecture
前端模块地图

新状态该落在哪一层，纯函数层的边界在哪。

  • 新状态进 app/ 模块，存量顶层不动
  • logic/ 唯一允许的宿主外 import 是 i18n.js

工程

这条判据救过一次删库。

12workflow
测试跑在哪：白名单在宿主机，其余进容器

归类决策、check 链上的 12 道门禁，以及两处覆盖盲区。

  • 白名单而非危险命令清单：代价不对称
  • tests/infra/ 的编排脚本不在任何门禁覆盖范围

每张图旁边有同名 .json 规格源（点开图后可在同目录取），改完规格用 archify 重新出图即可。
