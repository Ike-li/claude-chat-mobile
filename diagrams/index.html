Claude Chat Mobile 架构

一台电脑上的本机服务，把这台电脑的 claude CLI 接到手机浏览器。在手机上发消息时，server 通过 Agent SDK 拉起 CLI；坐在电脑前用终端时，server 不碰那个进程，只读它写到磁盘的 transcript，在手机上显示成只读镜像。同一个会话，同一时刻只有一端能写。

  • 运行时代码约 5.2 万行
  • 后端 7 个域 · 前端零构建
  • n=1 自托管，单用户

两条驾驶通道

选一条路径，看数据怎么走；点任一方框，下方会显示它对应的代码位置和职责。

单驾驶员

共享 transcript 不等于两端可以同时写：两个独立回合同时跑，会让上下文分叉、改同一批文件。所以手机端有三种状态，判定在 mirror-engine.js，判形态的纯函数在 sessions/history.js。

断线回放

出向只有 agent:event 一种信封，带 seq 与 epoch。手机切后台再回来时，先从实例的环形缓冲补，补不上再读盘。

鉴权与范围

五层各证明一件事，互不替代。

代码分布

后端 app/src/ 按域分成七个目录，前端零构建。条长按行数画，同一刻度，数字是 2026 年 10 月统计的约数；砖橙色是单个大文件占的部分。前端 app.js、server/app.js、agent.js、history.js 四个文件合计约 2 万行，约占运行时代码四成，改同步、回放、镜像时绕不开它们。

单个大文件 同目录其余文件 未列出：index.html、app.css 及若干小文件

模块边界

  • 前后端互不 import，唯一例外是 app/public/js/canonicalize.js（设备指纹规范化）
  • shared/ 是叶子，不得反向 import 其他后端域
  • server/ 是组装根，只有 app/server.js 和它自己能 import
  • 运行时不得 import scripts/ 与 tests/，零循环依赖

由 tests/gates/check-import-boundaries.js 在 npm run check 里拦截。

运行时代码之外

  • desktop/：macOS 菜单栏 CCM.app（Swift）与四个 launchd 模板
  • scripts/：用户要敲的命令，setup、config、doctor、service、uninstall、device、qr
  • tests/：unit、invariants、integration、e2e、smoke、playground，gates/ 下是门禁脚本
  • 宿主机只跑白名单命令，其余测试进容器

状态存在哪

数据位置说明
Claude 对话~/.claude/projects/唯一真相源，本项目不复制
Web 实例运行态AgentSession 内存流式回合、审批、事件缓冲；最多 20 个实例，空闲 30 分钟回收
控制面CCM_DATA_DIR会话指针、设备、审批、审计、推送订阅、已读位点、附件
已连接的文件夹ccm.config.json · WORKDIRS首项是主工作目录，改动热加载
无文件夹会话数据目录 scratch-workspaces/删会话时一并删除
终端会话状态与信号~/.claude/ccm/hooks 与 statusline 两个桥，可选安装，卸载对称移除
额度墙自动继续server 内存重启即作废，不落盘
