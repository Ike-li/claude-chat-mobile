- **Reading Time**: ~10 min

离线通知与运行态展示属于尽力而为的体验增强：通知通道偶尔失败绝不阻塞核心交互；状态栏按当前的驾驶方选择数据源，不混拼。

## 离线通知：两条通道

两条通道由 `app/src/ops/notify-channels.js` 统一调度，可以同时开：

| 通道 | 配置 | 适用 |
| --- | --- | --- |
| Web Push | VAPID_PUBLIC_KEY / VAPID_PRIVATE_KEY / VAPID_SUBJECT ，三项全齐才启用；需要 HTTPS | 系统级通知，点开直达该会话。Android 的 Chromium 系经 Google FCM，iPhone（Safari 16.4+ 且已添加到主屏幕）走 Apple 的推送服务 |
| ntfy | NTFY_URL / NTFY_TOPIC ，私有实例加 NTFY_TOKEN ；点开深链靠 PUBLIC_URL | 全程不经 Google；iOS 在局域网 http 下用不了 Web Push 时的替代。标题带工作区与会话标题，请自托管或用私密 topic |

- 通知标题带身份： 「事件 · 项目 · 会话」三段，锁屏上就能看出是哪个工作区的哪个会话。
- 正文默认最小化： 设置里可以开「锁屏带内容预览」，让锁屏通知带上问题、工具或任务摘要；ntfy 的正文恒最小化。
- 可自检、可关闭： 设置里有「发一条测试推送」，不必等真实审批出现才发现通道不通；推送订阅也能关掉，改预览开关不会把已关掉的推送偷偷订回来。

## 推送抑制：该推的一定推

> **TIP:** 推送判定铁律 — 审批、提问、后台任务完成无条件推送（用户可能锁屏或正在别的 App）。只有回合完成的 result 与网关静默告警（system 信封里的 gateway_stall notice），才会在「approved 房间有前台可见连接」时被抑制，两者共用 notifyHasClientsAtSend 这一条判据。

- 前台判据： 客户端上报的 client:presence （Page Visibility）， 不是 socket 连着没有。
- 「后台任务完成」只算真后台任务： CLI 把跑得久的前台 Bash 也建模成 task、走同一条 task_notification ，靠 CLI 在任务开始时带的 is_backgrounded 标记过滤掉。删了这道过滤，每条跑几秒的命令都会推到锁屏上。
- 节流： 同类通知的最小间隔为 NOTIFY_THROTTLE_MS （默认 60 秒，可显式设 0）。

## Statusline 状态栏：按驾驶方选数据源

| 场景 | 数据源 | 展示 |
| --- | --- | --- |
| Web 驾驶中 | SDK 运行态，开箱即用 | 底栏常驻摘要；展开看模型、分支、ctx 占用、5h 与 7d 额度用量和重置倒计时、预估花费，可一键复制 |
| 终端驾驶中（Web 只读镜像） | CLI statusline 快照 | 需安装可选的 statusline bridge（ npm run statusline:install ），同步 CLI 的模型、思考强度、上下文、成本与额度 |

两路数据**禁止混拼**：唯一的例外是额度这种账号级数据可以回落，且必须标注为非实时。展示语义以产品仓的 `docs/display-contracts.md` 为准。

## 两条轴：「需要你」与服务告警绝不混判

- 「需要你(N)」： 顶栏 chip 与角标只表达「点一下就能处理」的待办，也就是审批与提问。推送投递失败这类事混进来，用户点进去发现无事可做，这个数字就失去了意义。
- 服务告警： 推送投递失败、登录限速锁定、客户端错误这类，只出现在会话抽屉的「服务」小节与服务状态面板里。
- 服务状态面板： 四段，基础信息、判定化告警、安全日志、重启记录。不展示裸计数器，原始计数留给 /metrics ；每条告警说得出「是谁、为什么」，24 小时后自动退场。

## 运行中的动态行

- 动态状态行： 回合进行中显示与终端同款的进行时动词、秒表与等待提示（例如「仍在等待响应」）。
- 收尾行： 回合结束留一行过去时动词与耗时，对齐 CLI。
- 额度墙横幅（dev 已合入，尚未发版）： 撞上用量额度墙时，输入框上方出现横幅，按所处状态给一个按钮：已布防时可「取消」，只给选项时可「到点自动继续」，错过重置点或无法确认安全时给「继续」由你手动发。
