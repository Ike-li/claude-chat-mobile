# 测试怎么写

**这份回答「怎么做」**：写在哪一层、怎么知道自己没写出假绿、增删改功能时分别做什么。
**「有什么」在 [tests/README.md](../tests/README.md)**：目录地图、执行槽 S0–S7 的定义、不变量编号的词汇表。
看到 `// 守护：SRV-003` 不认识，去查那一份；不知道这个测试该写成什么样，看这一份。

规则都带案例。抽象原则会被"我这次是例外"绕过，带日期的事故不会。

---

## 0. 三条铁律

违反这三条会毁掉这台机器上的真实数据，不是"测试写得不好"的量级。

**① 宿主机只允许跑四条**：`npm run lint`、`npm run check`、`npm run test:unit`、`npm run test:e2e`
（加同档的 `npm run test:invariants`、分片并行的 `npm run test:e2e:parallel`，以及若干同源别名，
名单在 `tests/gates/guard-host-tests.js`）。
**其余一切会跑测试的命令一律进容器。**

这是白名单不是黑名单。黑名单要求「每遇到一个新命令都正确归类」，而那正是 2026-08-02 失败的那一步——
`npm run mutate` 没被归类成破坏性操作，它把用户 `~/.claude/projects` 整棵树删光了（70 个项目 / 291 memory / 2990 transcript）。
白名单反过来：不在名单上的默认进容器，判断错了顶多多跑一次容器，代价不对称地小。

> ⚠ **`guard-host-tests.js` 返回的是 `permissionDecision: "ask"`，不是 `"deny"`。**
> 它给提示并请求确认，不是硬闸；在自动批准的权限模式下直接放行。**别把它当安全网。**
> 真正的隔离来自容器边界。（2026-09-05 实测：`test:invariants:server` 在宿主机上照跑不误，
> 没有污染是因为那些用例自己注入了一次性 `CCM_DATA_DIR`，不是因为钩子拦住了。）

**② 变异（`mutate`）无例外进容器。** 它故意把源码改坏再跑测试，而被改坏的**可能恰恰是算删除路径的代码**——
上面那次事故里 `getProjectDir` 被改成恒返回 `''`，`join(真实根, '')` 塌成真实根本身，测试的 `rmSync` 就打上去了。
容器里 `HOME` 是一次性目录，这道防线不依赖任何代码正确性。

**③ 删除与写入目标必须落在一次性目录**（`mkdtemp`）。隔离要素共五件：
`HOME`、`CCM_DATA_DIR`、端口、工作目录、`~/.claude`。
**漏掉 `HOME` 会让 hooks 类测试删掉生产投递箱**（2026-09-01 撞过）。
测不到真实 `HOME` 不是缺陷，是这套方案成立的前提（`TEST-01`）。

写删除相关代码会撞上 `check-destructive-deletes` 门禁：测试里的 recursive 删除必须可追溯到 `mkdtemp`，
否则写 `// safe-rm: 理由`；生产代码里「追不到一次性目录、目录段由代码算出」的单文件删除写 `// safe-path: 理由`。
**两种标记不通用**——为单文件删除批的豁免不放行递归删除。

## 1. 动手前的三个判断

按顺序问，顺序错了会写出一堆永远不红的测试。

### 判断一：碰哪条不变量？——这一条同时决定文件放哪棵树

先去 [tests/README.md](../tests/README.md) 的编号表里找。**结果直接决定目录，没有第二个判据：**

| 编号表里 | 文件放哪 | 文件头 |
|---|---|---|
| **找得到** | `tests/invariants/`（S2 放 `server/`，环境级放 `env/`） | 必须写 `// 守护：<编号>（一句话复述那条红线）` |
| **找不到，且这个改动不碰任何红线** | `tests/unit/`，按被测模块命名 | 不写「守护：」行（那是 invariants 的准入声明） |
| **找不到，但它确实是一条红线** | 先把它写进编号表，再按第一行走 | 同第一行 |

这不是风格建议，是 `npm run check` 里 `check-invariant-ids.js` 的硬判定：
`invariants/` 下缺「守护：」行、守护行里没编号、编号在表里查不到、表里登记了却整棵 `tests/` 树无人提及——四种都红。

**第三行要谨慎。** 编号表是产品红线的枚举，不是"我需要一个编号所以加一个"。
判据是：**这条跨版本必须成立吗？违反了会伤到用户吗？**
交互调参（滑动阈值、时间分隔行的疏密）不是红线，归 `unit/`；
"删除失败不得谎报成功"、"`/health.busy` 不得把在跑报成空闲"是红线，值一个编号。

> 2026-09-05 加这道闸时，它当场抓出 4 个放错树的文件——3 个是纯前端交互（搬去了 `unit/`），
> 1 个是真红线但从未登记（补登为 `OPS-04`）。**在那之前这 4 个文件不会让任何东西变红。**

改了带既有编号的代码（`SEC-*` / `FILES-*` / `REL-*` / `SRV-*` / `OPS-*`），
**先看编号表里对应的那条不变量**——那些编号标的是修过的坑，不是装饰。

### 还有一套编号不在表里：`RN`（review 局部序号）

`// R7（2026-08-06）` 这类是**某次 review / 需求合稿的内部序号**，不是全局不变量，不进编号表。
它们**靠日期消歧**——`R1`/`R2`/`R3` 在 2026-08-06（BUG hunting review）与 2026-08-10（真机排障）
两批里各有一套，撞号；`agent-lifecycle.test.mjs` 里两批都有，所以那里的用例名写成 `R3(08-06)`。

**碰到 `RN` 只有一条规矩：别删日期，也别新引用一个没有日期的 `RN`。**
日期是它唯一的锚——2026-09-05 清理时发现 `R65` 那 12 处（8 处在生产代码）的锚原本是一份
gitignored 草稿，草稿没了，编号就成了只有当时在场的人能解的密码。已就地补成 `R65（2026-08-30 需求合稿）`。

> 顺带一条删除指针时的判据：先分清那个指针是**唯一的语义锚**还是**冗余的出处标注**。
> `SRV-003` 那种有编号表兜底，指针删了没事；`R65` 的唯一锚就是那份草稿，删指针会让它从
> 「锚在不存在的文件上」变成「完全没锚」。**先安置，再删指针**——那次我做反了顺序。

### 判断二：这条不变量的观察点在哪一层？

**不要问「需要真 CLI 吗」，那是个太粗的问法**，它会把「需要 spawn 成功」和「需要模型产出」混成一档。

2026-09-05 的实例：`MSG-01` 与 `SOCKET-01` 曾被判给 S5（真 Claude），
理由是「假 CLI 只应答 `--version`，驱动不了 agent turn，所以证不了 send ≤ 1」。实测推翻：

- **ack 路径不等 turn**：首条 `user:message` 的 ack 实测 **14ms** 返回。懒开实例只要求 spawn 成功。
- **send 次数外部可观测**：`emit('user_message')` 与 `queue.push()` 在同一条直线上、中间无 await，数气泡就是数 send。
- **`SOCKET-01` 要证的是服务端状态跨越一次断开没变**，那份状态不依赖 CLI 产出任何东西。
  假 CLI 不吐 result 反而让条件更强——轮次永远停在「运行中」，于是有了持续存在的观察对象。

代价是这两条不变量在默认路径上一直零覆盖。**正确的问法是「这条不变量的观察点在哪一层」。**

### 判断三：失败方向是什么？

「fail-closed」在本产品里是**逐条选过的**，不是「任何异常都拒绝」。有几条的正确方向恰恰是**不拒绝**，
写一条「所有 catch 都必须 403」会把它们测反：

| 情况 | 规定方向 |
|---|---|
| 无 token / 空白 token | 拒绝启动 |
| 公网 Host 上 JWT 失败 | 拒绝，**不**回退 `AUTH_TOKEN` |
| 路径越界 / symlink 逃出工作区 | 拒绝，记审计 |
| 打开 FIFO / 字符设备 / unix socket | **`open` 之前**拒绝（否则整个 Node 进程卡死，无自愈） |
| 审批指纹不符 / TTL / 重启时的 pending | 不可再执行 |
| `files:write` 的 `baseHash` 与磁盘不符 | 拒绝，不静默覆盖 |
| 配置 JSON 语法错误 | 抛错，**不**回落另一份文件 |
| 面板写入目标 ≠ 启动读取目标 | 视为假成功——必须测到「写了等于没写」会被抓住 |
| `trusted-devices.json` 瞬时读失败 | ⚠ 保留内存 last-good（避免本机被 flap 锁死）——**反直觉方向** |
| 鉴权已通过后 handler 抛 500 | ⚠ **不得**记一次认证失败、不得锁限速桶——**反直觉方向** |
| 推送 `result` 且尚未上报 presence | 视为前台，**不推**（保守，避免误炸） |
| 上传 `saveAttachments` 抛磁盘类错 | ack 标 permanent，**不**让离线队列永久重试 |

每条测试只问一件事：实现是否还是这个方向。

## 2. 唯一允许的假

**只有 Claude CLI / Agent SDK 的模型回合。**

这条边界切的是**「模型是否开口」，不是「进程是否真实」**。spawn 一个真 CLI 二进制探 `--version`、
观察进程表、发信号收尸——零 token，属于可以做真的部分。

下列对象被测时**必须是真的，mock 掉等于没测**：

- 文件系统、`realpath`、symlink、FIFO、文件权限 `0600`
- Git 工作区（status / diff 的路径门）
- Socket.IO 与 HTTP（含握手、ack、限速桶）
- 子进程的退出、管道、超时（含 Swift `CCMProcess`）
- `trusted-devices.json` 的文件监听
- 配置文件的实际读写目标

前端可以打协议兼容的假后端（`tests/e2e/mock/`），但它的事件 `type` 与入向事件名
**必须与 `app/src/shared/protocol.js` 同一份名单**；字段语义与真 server 漂移是 S4 要单独堵的缝。

假 CLI 有两档（`tests/fixtures/fake-claude.sh`）：不设 `CCM_FAKE_CLAUDE_MODE` 时吞 stdin、不产出任何输出；
设了才走可驱动的 Node 实现（应答 initialize、吐 `system/init`，`turn` 档还吐 `result` 让回合收尾）。
**默认行为是显式 opt-in 保护的**——五个 S2 文件与 21 个集成文件建在「stub 永不产出、实例恒 busy」这个前提上。

## 3. 怎么知道自己没写出假绿

这一节是本文档的核心。**看着漂亮、永远不会红的测试比没有更坏**——它占着"这里测过了"的位置。

### 两侧验收：绿的一侧不算验证

一条测试要同时满足：**正常代码下绿**，**注入对应缺陷后红**。只跑过绿的一侧，等于没验。

注入的方式就是手改源码跑一次再 `git checkout` 还原，不需要工具。要点是**注入的缺陷必须是这条断言声称能抓的那个**。

> 2026-09-05：`file-preview.test.mjs` 的文件头一直声称守护 `FILES-3`（`O_NOFOLLOW` 防逃逸）
> 与魔数识别。变异实测发现**两者都没有任何断言**——文件头写的和文件里有的是两回事，
> 而没人会去核对文件头。

### 绿侧要跑够次数

race-prone 的用例，一次绿不算"稳定绿"。

> 2026-09-05：SRV-001 的用例我基于**一次**绿跑写下「双向验收都做了」，
> 重跑时 **3/3 全红**。根因是我把不变量读反了（`fresh:${cwd}` 单飞防的是跨 cwd 坍缩，不是同 cwd 重复），
> 而且 busy 闸在 cwd 路由之前生效——那条并发路径**架构上不可达**。
> 三种构造都试过，正常代码与注入代码产出逐字相同。最后作为「不可达」关闭，不是作为「未做」。

### 正对照：仪器要先证明自己看得见

测「没有 X」的时候（没有泄漏、没有重复、没有副作用），先构造一个**真的有 X** 的场景，确认测试会红。
否则「0 泄漏」和「看不见泄漏」在结果上完全一样。

> 2026-09-05：`RESOURCE-01` 第一版盯 `createHooksInbox` 的 `fs.watch`，正对照直接失败——
> `getActiveResourcesInfo` 对 unref'd watcher 失明，darwin 的 FSEvents 也不消耗可见 FD，四个指标全看不见。
> 那一版是**永远绿的**。改盯 `approval-store` 非 unref 的 `_saveTimer`（20 次写入必须只剩 1 个 timer）才成立。

### 几个反复出现的假绿形态

- **给既有代码补的测试默认空过**——它是照着现有实现写的，实现错了它跟着错。补完必须注入验红。
- **fixture 编错外部契约时恒绿**——夹具和被测代码一起偏离真实契约，两边自洽。判据是拿真实数据形态核对夹具。
- **为通过而设的 `sleep` 是缺陷窗口的负片**——加 sleep 才能过的地方，正是那个窗口有 bug 的地方。
- **用例建在缺陷窗口外**——修复后全绿，但用例根本没覆盖到出问题的那个时刻。写完问一句"这条在修复前会红吗"。
- **判「警告是否显示」查 `classList` 不查 `textContent`**——文本在 DOM 里但元素是 hidden，textContent 照样有。
- **mock 数据每次现算**——E2E mock 里时间戳用 `Date.now()`，于是"不重建 DOM"这类优化从未被真正验证过。

## 4. 写成什么样

### 命名

**按生产模块命名，不按测试流派命名。** 没有 `security.test.mjs` / `reliability.test.mjs`——
安全、故障、竞态是**问法**，填进对应模块的文件里。

文件名与生产文件同名：`file-browse.js` → `file-browse.test.mjs`。
**这不只是美观**——`mutate` 默认自动查找「提到该生产文件的测试」，同名让自动匹配生效，省掉每次手写 `--tests=`。

大模块按主题拆，拆的轴是主题不是行数：`agent.js` 一个生产文件拆成 15 个 `agent-*.test.mjs`。

### 文件头

`tests/invariants/` 下每个文件头四行，缺一行就说明有一个判断没做：

```js
// tests/invariants/xxx.test.mjs —— 一句话说这是什么
// 守护：APPROVAL-01（一句话复述那条红线）
// 测什么：……
// 不测什么 + 为什么：① …… 属 S3 ② …… 需真模型，归 S5
// 槽位：S1（纯函数 + 一次性目录真 fs）
```

**「不测什么」是必写项。** 它逼你说出边界在哪、那部分归谁——没有它，读者无法判断
一个没被覆盖的场景是"有意不测"还是"忘了"。

### 断言消息

失败消息要说**失败意味着什么**，不是复述期望值。测试的诊断价值全在失败那一刻。

> 2026-09-05：`mirror-sync.test.mjs` 里 13 条断言的消息写着「待实现：mirrorReleaseStep」——
> 那是三个月前函数还没实现时写的。函数早已实现、用例早已全绿，但这些消息一旦真红，
> 会把人推向"去实现它"而不是"去看谁改坏了导出"。**过期的断言消息会在最需要它的时刻说谎。**

### 源码文本断言：两类，处置相反

`assert.match(readFileSync(src), /…/)` 这种断言分两种，别一刀切：

- **权宜之计**——因为组装根加载不了、当时没有第二条路，才退而求其次比源码文本。
  改个变量名就无故变红，保持文本不变而改坏行为照样绿。**这类该搬去行为层。**
- **架构守卫**——`assert.doesNotMatch(src, /\blet everConnected\b/)` 这种"某个变量不得存在"。
  **没有行为等价物**：一个把状态搬回 `app.js` 顶层、还维护得完全正确的实现，在行为层完全合格，
  而那恰恰是要挡的。**这类该留。**

搬走之前先确认它是哪一类。判据是问：有没有一个行为层的断言能表达同一件事？

## 5. 变异检查怎么用

**它不是门禁，是单文件按需诊断**（`npm run mutate:docker -- <文件>`）。不进 CI，不设门槛。

用在：算路径、删除、scope、鉴权比较这类代码改完之后。
存活的变异体 = 断言没咬住，补的是**断言**，不是新的测试层。

### 存活 ≠ 缺陷

等价变异、不可达的防御性兜底、纯日志、死返回值都会合法存活。
2026-09 系统量过全部后端域：1701 个变异体、444 个存活，抽样约 60 个，真缺陷率约 1/6。
**别把"清零存活"当目标**，逐条问「这里改了你会在意吗」，在意就补，不在意就放过。

### 它看不见什么

**算子只有 9 个，全是运算符/字面量替换**（`===`↔`!==`、`&&`↔`||`、`>=`→`>`、`true`↔`false` 等）。
它表达不了「删掉一次方法调用」「换一个算法」「少传一个参数」。

> 2026-09-05：`canonicalize.js` 用两个测试集分别跑变异，杀伤**完全相同**（都是 15/17，存活的还是同两个），
> 据此差点判定旧测试冗余可删。实际注入「排序比较器不做 NFC 归一化」——**旧测试红，新测试全绿**。
> 旧测试有真独占能力，只是那个缺陷不在变异算子的表达范围内。
> **「变异杀伤相等」只等于「在算子能表达的改动上相等」，不等于「测试能力相等」。**

### 分母太小的不参与排名

`fingerprint.js` 1/1、`audit.js` 1/5、`format.js` 0/1 这种，比率没有意义。
排名只看分母 ≥ 16 的。

## 6. 增 / 改 / 删功能时做什么

### 加功能

列一张表：行是「这个功能会怎么伤人」，列是槽。不适用的格子写「—」和原因。
两个填好的真实例子，照着这个粒度写：

**附件上传**

| 会怎么伤人 | 槽 |
|---|---|
| 文件名穿越、上限数字前后端不一致（`FILES-4`） | S0 对照 + S1 |
| 真写盘、`0600`、越界文件名 | S1 / S2 |
| 未认证 / 未审批也能发附件 | S2（与其它写入共用门表） |
| UI 选文件、超限报错 | S3 |
| Claude 真读到 | S5 |
| 写一半时目录被换掉（`FILES-2`） | S1/S2 fail-closed；无事故不升 S5 |

**发消息**

| 会怎么伤人 | 槽 |
|---|---|
| 两阶段去重、in-flight claim、**FRESH 分支**（`SRV-001`） | S1 |
| 重复 ID 的 ack + 假 CLI 上 send ≤ 1 | S2 |
| 流式渲染、停止键 | S3 |
| 真回复、真中断、真 resume | S5 |
| 终端占用时拒绝发送 | S1 夹具；真链 S5 |

完成判据：

- 该红的格子有一条**外部可观察**的断言（用户看得见的行为、公开契约、失败方向），不是私有方法名。
- 更便宜的槽能抓住的，**没有升到 S3/S5**。
- 路径 / 删除 / 鉴权相关的，变异至少对过改动文件。
- **不新增执行槽**，不新建 `security/` `reliability/` `performance/` 顶层类别——那些是问法，填进表里。

### 交付前：把验证过程写进 commit，不要只说"测了"

项目的 commit 约定里有 `Tested:` / `Not-tested:` trailer（见根 `CLAUDE.md`）。
**两侧验收的证据就写在那里**，一条测试一行，形如：

```
Tested: 注入 `live: 0` 到 app.js:3322 → unread-on-entry 精确红 1 条（"后台累积的未读必须随 ack 带回，实际 0"）
Tested: 容器全链五段 rc=0（unit 3570 / invariants 532 / :server 53 / :env 13 / integration 101）
Not-tested: e2e 未跑——本次零生产代码改动且未触及 tests/e2e/
```

这不是形式主义。**没有留痕位置的规则，只约束得住诚实的人**——
写「已做双向验收」零成本，写「注入了什么、哪一条红了、消息是什么」写不出来就是没做。

> 2026-09-05：我自己就基于一次绿跑写下过「双向验收都做了」，重跑 3/3 红。
> 如果当时被要求写出注入的是什么、红了几条，那句话根本落不下笔。

### 改行为

**先改断言，再改实现。** 展示契约类的尤其如此（`docs/display-contracts.md` 已明文要求
「改契约先改 `tests/unit/display-contracts.test.mjs`」）。

反过来做的话，你是在让测试追认实现，而不是让测试约束实现。

### 删功能 / 退役测试

删测试文件比删生产代码更需要证据——生产代码删错了会有测试红，测试删错了**什么都不会红**。

2026-09-05 退役 `canonicalize.test.mjs` 的完整流程，可以照抄：

1. **变异对比**：同一个生产文件，分别用「只有新测试」和「新旧都在」两个测试集跑变异，看差集。
   两轮变异体总数相同才可比（总数不同说明覆盖行集不同，结论无效）。
2. **注入实验**：变异说"没多杀"不等于冗余（见上一节）。逐条读旧测试的独占断言，
   为每一条构造对应缺陷，看新测试会不会红。
3. **先搬能力再删**：真独占的搬进新文件，每条搬入的断言各自过一遍两侧验收。
4. **删除后核对数字**：`test:unit` 的 test 数减少量必须**正好等于**被删文件的 test 数。
   对不上说明有附带影响。（那次是 3593 → 3578，差 15，与被删文件的 15 个 test 精确相等。）
5. 在新文件头写清**哪些没搬、为什么**——否则下一个人会以为是漏了。

### 发版时

发版不是再开一层，是横切一刀。至少证明：

1. S0 绿（本版本动了 `desktop/` 的话含 Swift；改了菜单栏还要真编出 bundle——`check` 里的 typecheck 不产出 bundle）。
2. 服务能带着非空 `AUTH_TOKEN` 起来，`/health` 为 ok。
3. 未持令牌进不了 `/metrics` 与 socket 业务事件。
4. 新设备待审、批准后可操作、吊销后已连连接失权——S2 即可。
5. `npm run test:smoke` 的四条故事：core、reconnect、upload、entrypoint。
   动了单驾驶员再加 handoff，动了审批再加 permission。
6. 文件越界仍拒绝（S1/S2，不烧 token）。
7. 分发包能安装并启动；卸载后 `~/.claude/projects` **还在**（两侧断言，`DIST-01`）。

PR 默认只跑 S0–S3。S5 不是「在 PR 上持续缺席」——它本就不该出现在未授权的 PR 上。

## 7. 行业常用名怎么落到这里

有人（或某个模型）说"该补集成测试了"、"要加一层安全测试"时，先把那个词翻译过来。
**它们在本项目不是并列的十五层，而是槽或问法。**

| 常用名 | 落到这里 | 不要把它当成 |
|---|---|---|
| 静态质量检查 | S0 | 再叠一道泛 SAST 与 import 边界同闸 |
| 单元测试 | S1（纯函数 **+ 真磁盘**） | 「unit 里必须 mock fs」 |
| 后端接口测试 | S2 的 HTTP 面（健康、指标、推送、静态壳） | 每个 REST × 九种反例 |
| Socket.IO | S2 的**主面**（产品在这里，不在 HTTP） | 与 HTTP 对等的另一层 |
| 模块集成测试 | S2（真组装根 + 假 CLI） | 与 S2 平行的新层 |
| 真实依赖集成 | S5（真 Claude）；fs / git / socket 在 S1/S2 已经要求为真 | 给文件系统再单开一层「真依赖」 |
| 前端功能测试 | S1 的 `logic/*` + S3 | 再加一个组件测试层 |
| 端到端 E2E | S3 UI 穷举；S4 薄跨缝；S5 真 Claude 故事 | 「浏览器 + 真 Claude」一条必建 lane |
| 安全测试 | **问法**：AUTH / DEVICE / SCOPE / 上传，填进 S0–S2 | 第三套 `security/` 断言 |
| 可靠性 / 故障注入 | **问法**：重启 pending、进程死、配置坏、ENOSPC。能 S1/S2 就不上 S5 | chaos 平台 |
| 并发与竞态 | **问法**：同一 `clientMessageId`、approve/deny 同时、symlink 顶替 | 独立的一层 |
| 性能与资源 | `RESOURCE-01`（开合 N 次后句柄不随 N 涨） | QPS、24h soak 进 PR |
| 兼容性 | Node 声明的最低 + 当前；CLI 靠上游守望；Safari 发版手测 | 每 CLI × 每浏览器的 PR 矩阵 |
| 安装 / 升级 / 卸载 | `DIST-01` + `tests/invariants/env/` | 只当文档附录 |
| 冒烟与回归 | 发版横切（上一节） | 再开一个 runner |

## 8. 明确不做

这些是已经决策过的，别用测试去重开：

- 按测试流派重组目录，或新增 `security/` `reliability/` `performance/` 作为层。
- 每个 HTTP / Socket 入口 × 九种反例的笛卡尔积。HTTP 面只有健康、指标、推送订阅和静态壳，产品在 Socket。
- 把 SAST / SCA / 密钥扫描绑进与 import 边界同一道必绿闸。本产品的危险 API 用
  「删除目标是否由代码算出」「spawn 是否走参数数组」这种锚在**形态**上的闸。
- 为覆盖率去加载 `app.js`；把覆盖率门槛当健康度。
  （2026-09-04 已退役三个发假绿灯的门禁——覆盖率那个的「✅ 达标」与「11 个核心文件 0 覆盖」是同一次打印。）
- 24h / 72h soak 进必绿。有泄漏信号再用 N 次开合的 `RESOURCE-01`。
- 把真 CLI 探针 / 上游 schema 嗅探排进 nightly。上游漂移靠守望开 issue。
- 用测试去重开 `docs/hard-rules.md` 里已决的「不做」（AD-5 / SP-10 / UP-1）。
- 在宿主机真实 `HOME` 上跑变异、真 Claude、或任何 recursive 删除。

## 9. 日常一句话

改代码前先问**伤害域**，不是先问「unit 还是 e2e」。

能写成 `logic/` 或后端纯函数的，先写一条会红的 S1。
接线（握手、ack、热加载、文件监听）走 S2。
用户看得见且 S1/S2 看不见的，走 S3。
假后端可能撒谎的那几条用户路径，走 S4。
只有模型或真 CLI 进程表才能撒谎的，走 S5。
算路径的代码改完，走变异。

红了先看是不变量被打破，还是**测试碰到了真实 `HOME`**——后者是测试自己在犯规。
