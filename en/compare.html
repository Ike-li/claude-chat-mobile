Honest comparison

Should you use this, or the official Remote Control?

Short answer: most people should use the official Claude Code Remote Control. It ships with your Claude subscription, takes one command, and there is no server to run or secure. This page exists to tell you the specific cases where it cannot work — those are the only reasons to self-host something like this project.

Facts about Remote Control below are from the official Claude Code documentation · Checked 2026-09-22

Use the official Remote Control if none of the rows below apply to you Run /remote-control in any Claude Code session, scan the QR code with the Claude app, done. Nothing to install, no ports opened, no server of yours to keep patched. If it works for your setup, it is the better choice and this project has nothing to add.

When the official Remote Control cannot work

These are hard requirements from Anthropic’s own documentation, not opinions. If any row matches your setup, Remote Control is unavailable and a self-hosted bridge is one of the few remaining options.

Your setupWhat the official docs say
You authenticate with an API key “API keys are not supported.” Remote Control requires a claude.ai sign-in on a Pro, Max, Team or Enterprise plan.
You point ANTHROPIC_BASE_URL at a third-party gateway, relay or proxy Not available when the variable points “at a host other than api.anthropic.com, such as an LLM gateway or proxy.” (Allowed before CLI v2.1.196; tightened since.)
You run on Amazon Bedrock, Google Cloud’s Agent Platform or Microsoft Foundry Explicitly listed as unavailable API-endpoint configurations.
You set DISABLE_TELEMETRY, DO_NOT_TRACK, CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC or DISABLE_GROWTHBOOK Each one disables the feature-flag evaluation Remote Control depends on. You must unset it to use Remote Control.
Your organization requires Zero Data Retention “Organizations with compliance requirements such as Zero Data Retention can’t enable Remote Control.”

Where the transcript lives

This is the other real difference, and it cuts both ways.

  • Official Remote Control: while connected, the session transcript — your messages, Claude’s responses and tool activity — is stored on Anthropic servers. That is what keeps the conversation in sync across your devices and lets a session survive a network drop. Execution and filesystem access stay on your machine.
  • This project: the transcript stays in the same local files your CLI already writes. Nothing is stored off-machine. The trade-off is that cross-device sync and reconnect are your server’s job, not Anthropic’s.

What is not a difference

Your computer has to stay on either way Both approaches drive a claude process on your own machine. If the machine sleeps or the process exits, the session goes offline. Self-hosting does not buy you a session that runs without your computer — if that is what you want, neither of these is the answer.

What you take on by self-hosting

Stated plainly, because it is the part comparison pages usually leave out:

  • You run and update a Node server, and you decide how it is reachable — LAN, a tunnel, or Cloudflare Access. The project is locked by default and refuses to start without a token, but the exposure decision is yours.
  • One instance serves one user. There is no multi-tenancy and none is planned.
  • Push notifications need your own web-push keys or an ntfy topic; there is no managed service behind it.
  • No official mobile app — it is a PWA you add to the home screen.

FAQ

Should I use Claude Chat Mobile or the official Claude Code Remote Control?

For most people, the official Remote Control. It is included with a Pro, Max, Team or Enterprise plan, needs one command, and there is no server to run or secure. Claude Chat Mobile is for the cases where Remote Control is not available: API-key authentication, a third-party gateway or proxy via ANTHROPIC_BASE_URL, Bedrock / Google Cloud Agent Platform / Microsoft Foundry, or a setup where the session transcript must not leave your machine.

Does Claude Code Remote Control work with an API key or a third-party gateway?

No. The official documentation states that API keys are not supported, and that Remote Control is unavailable when ANTHROPIC_BASE_URL points at a host other than api.anthropic.com, such as an LLM gateway or proxy. Claude Chat Mobile drives your local CLI directly, so it works with whatever provider that CLI is already configured for.

Where is my session transcript stored?

With the official Remote Control, the transcript is stored on Anthropic servers while the session is connected, so it can sync across devices. With Claude Chat Mobile the transcript stays on your own machine, in the same files your local CLI already writes.

Does my computer need to stay on?

Yes, for both. Both approaches drive a claude process running on your own machine; if that machine sleeps or the process exits, the session goes offline. Self-hosting does not change this.
