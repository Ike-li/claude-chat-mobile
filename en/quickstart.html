Quickstart

Self-hosted mobile Web UI for your real local claude CLI—same agent, same CLAUDE.md, same session. Not a remote desktop, not multi-tenant SaaS.

Source of truth: README.en.md and Getting Started · Full Chinese handbook: docs-site · Updated 2026-09-24

Prerequisites

  • Node.js ≥ 20 — node --version
  • A working local claude CLI — which claude finds it, and it can finish a normal conversation in your terminal. This project drives your CLI; it does not install Claude or sign you in.
  • macOS or Linux (first-class). Native Windows is experimental; WSL2 is recommended.
Claude subscription or third-party gateway Model access belongs to the claude CLI, not to this project: every session loads the CLI’s settings for its workspace, so whatever works in your terminal works on your phone. A subscription only needs that account signed in. For a gateway, put ANTHROPIC_* in the env block of a CLI settings file (the workspace’s .claude/settings.local.json, or ~/.claude/settings.json); that also works for the service the macOS desktop app keeps running. Exporting them in the shell that runs npm start works for the headless entrypoint only. ANTHROPIC_* placed in this project’s ccm.config.json or .env are stripped at startup, and the startup log names each one.

Install and start

  1. Download the latest release and install runtime dependencies. 
    curl -fsSL https://github.com/Ike-li/claude-chat-mobile/archive/refs/heads/master.tar.gz | tar xz
cd claude-chat-mobile-master
npm ci --omit=dev
    master only moves on release, so this archive is the latest release. It leaves out the test tree and maintainer gates; to change code or run tests, git clone the full repository instead (same npm ci --omit=dev, plus a plain npm ci before running tests).
  2. Create the config. 
    npm run setup   # writes ccm.config.json (mode 0600): a random AUTH_TOKEN,
                # the project folders your phone may open (WORKDIRS; the first is the default),
                # and how your phone will reach this machine (ACCESS_PROFILE)
# no TTY (coding agent, CI):
node scripts/setup.js --yes --work-dir=/absolute/path/to/project --hooks=off
  3. Pre-flight check. 
    node scripts/doctor.js
node scripts/doctor.js --fix   # only tightens permissions on the config file and control-plane JSON
  4. Start the server. 
    npm start
# the startup banner masks the token and prints the addresses to open, e.g.
#   http://<lan-ip>:3000/#token=<YOUR_TOKEN>
# the full token is in ccm.config.json; node scripts/qr.js turns the address into a QR code
    AUTH_TOKEN is a startup prerequisite: without one the server refuses to start. There is no “local means no auth” mode.

Reach it from your phone

ScenarioWhat to do
Same Wi‑Fi Open http://<lan-ip>:3000/#token=<AUTH_TOKEN>, or scan the QR code from node scripts/qr.js. The server listens on all interfaces by default (BIND_MODE). On first load the browser stores the token and removes it from the address bar.
Temporary HTTPS (PWA install, Web Push) In another terminal: cloudflared tunnel --url http://localhost:3000, then open https://<random>.trycloudflare.com/#token=<AUTH_TOKEN>. To stay off Cloudflare, install Tailscale and run tailscale serve --bg 3000; node scripts/doctor.js prints the address. On iOS, Web Push also needs 16.4+ and adding the page to the Home Screen first.
Long-term public A fixed domain with Cloudflare Tunnel + Access, or Tailscale, another encrypted tunnel, or your own reverse proxy. Keep the server running with npm start under a supervisor of your choice, or with the macOS menu-bar app. See the Chinese handbook page 生产部署 and the repo’s docs/deployment.md.

First non-local connection: device approval

A valid token is not enough for a new device: its first non-local connection waits until you approve it. Use the macOS menu-bar app, tap Approve on another device you already trust, press Enter in the terminal running npm start (headless only), or use the command line:

node scripts/device.js list
node scripts/device.js approve <ID>

Only two kinds of connection skip approval: one already validated by Cloudflare Access, and a genuine local one (loopback peer and a localhost / 127.0.0.1 / ::1 Host). Traffic forwarded by cloudflared, nginx or an SSH tunnel also arrives from loopback, but with a public Host, so it still needs approval unless Access validated it. Set DEVICE_APPROVAL_SCOPE=all to require approval on every path.

Security This is a remotely reachable code-execution channel into your shell. Single-user per instance. Read the security model before exposing anything beyond your LAN: English Security Model · 中文安全模型 · README.en.md.

Security iron rules (quotable)

  1. One user per instance — not multi-tenant SaaS; anything that passes auth carries the permissions of the local account running claude.
  2. No token, no server — AUTH_TOKEN is a startup prerequisite under every bind mode, even for a browser on the same machine.
  3. Workspaces are allow-listed — files and sessions are reachable only inside WORKDIRS; do not add your whole home directory.
  4. New devices need approval — only Cloudflare Access–validated and genuine local connections skip it; DEVICE_APPROVAL_SCOPE=all removes those exceptions.
  5. CLI permissions are inherited — no second “Web super-allowlist”; review permissions.allow in your Claude settings before public exposure.
  6. The file editor writes directly — it skips tool approval (it is still scope-checked, size-limited, conflict-checked and audited); set FILE_EDIT=off for long-term public exposure.
  7. Not Anthropic’s official app — independent open source; drives your local CLI via the Claude Agent SDK.

Update

Update the way you installed. From the archive: go back to the directory you unpacked into (the parent of claude-chat-mobile-master/), re-run the same curl … | tar xz, then npm ci --omit=dev. ccm.config.json and data/ are not in the archive, so nothing overwrites them. From a clone: git pull, then npm ci --omit=dev. Either way, restart the server and re-run node scripts/doctor.js; on macOS also pick “更新桌面端（重新编译）” (rebuild the desktop app) in the menu.

If something fails

SymptomLikely causeWhat to try
Server exits right after npm start No AUTH_TOKEN (it is a startup prerequisite) Run npm run setup first; it generates the token
Phone cannot open the page on the LAN Not on the same network, a firewall, or BIND_MODE=loopback Use an address the startup banner lists. With BIND_MODE=loopback the banner says so: forward the port yourself, or set BIND_MODE=lan and restart
Token works but the UI stays locked Device approval pending node scripts/device.js list, then approve <ID> on the host
The page opens but chat fails claude on the host cannot finish a turn A specific CLI error on the phone means the link works. Get claude through one turn in your terminal, in the same workspace directory: /login for a subscription; for a gateway, check which settings layer holds ANTHROPIC_*, then read the MODEL_SETTINGS line of doctor
Startup log or doctor says ANTHROPIC_* were ignored They are in ccm.config.json or .env, where startup strips them Move them to the env block of a CLI settings file (or export them in the shell, headless only)
Port 3000 already in use The desktop app or an existing npm start Do not start a second server; restart from the desktop menu or in the same terminal, or change PORT

Optional

  • CLI hooks bridge — lets a session running in your terminal wake the phone when a turn ends or needs you: npm run hooks:install (check with hooks:status, remove with hooks:uninstall). It writes to ~/.claude/settings.json, and only when you run it.
  • Statusline bridge — shows the CLI’s model, effort, context, cost and quota on the read-only view of a terminal-driven session: npm run statusline:install (check with statusline:status). Explicit opt-in; it wraps your existing CLI statusline command.
  • macOS desktop app — a menu-bar console that keeps the server running: npm run app:install (needs the Xcode Command Line Tools).
  • Working on the code (full git clone only): npm run dev · pre-push gate npm run check.
Already running the server on port 3000? Do not start a second npm start “just to check.” Restart from the desktop menu, or in the same terminal for headless. See the Chinese ops page 运维与排错.
