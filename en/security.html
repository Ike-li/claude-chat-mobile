Security model

Read this before exposing the server beyond your machine. This project is a remotely reachable code-execution channel into your local shell—not multi-tenant SaaS, not Anthropic’s official mobile app.

Source of truth: README.en.md · Security Model · Chinese handbook: 安全模型 · Updated 2026-09-24

Danger Anyone who passes authentication has the same power you have at a terminal on that host. Do not run a shared instance for multiple people. Do not expose it to the public internet without a strong token, device approval, a review of your CLI allow-lists, and (recommended) Cloudflare Access or a private tailnet.

Is it safe on the public internet?

Only if you deliberately open it. This is a code-execution channel into your shell. There is no token-less mode: the server refuses to start without AUTH_TOKEN. By default it listens on all interfaces so a phone on the same Wi‑Fi can connect (BIND_MODE=loopback keeps it on this machine); reaching it from the internet takes a tunnel, a VPN or a reverse proxy that you set up. Before any public URL: review CLI allow-lists, approve only your own devices, and prefer Cloudflare Access or a private tailnet for long-term use. Details below.

Six rules

1. Single-user per instance

One operator, one instance. There is no multi-user account system or tenant isolation. Anything that passes auth carries the permissions of the local account running claude. Do not treat Claude Chat Mobile as multi-tenant SaaS or share one instance across people.

2. No token, no server

AUTH_TOKEN is a startup prerequisite under every bind mode. Without one the server refuses to start, before it listens on any port. Even a browser on the same machine needs the token: there is no “local means no auth” path. npm run setup generates a random 64-character token; the startup banner only ever shows it masked.

3. Workspaces are explicitly allow-listed

Files, sessions and related operations reach only the folders listed in WORKDIRS. Do not add your whole home directory for convenience: setup rejects the home directory itself as a workspace.

4. CLI permissions are inherited

No second “Web super-allowlist.” Auto-approve is the merged permissions.allow from your existing Claude config (global ~/.claude/settings.json, project, and local settings)—the same sources as the terminal. Matches run; everything else is suspended and pushed to the phone with full command + working directory.

Before public exposure Audit your global allow-list. Old broad Bash(...) / Write rules will auto-approve here too, without a phone prompt.

Web runtime modes (dontAsk / auto / bypassPermissions) and approval TTL are not “UI equals interactive terminal step for step”—shared is the settings source, not every interaction.

5. New devices need approval

A valid token alone is not enough. A new device’s first non-local connection waits until you approve it: from the macOS menu-bar app, from another device you already trust, by pressing Enter in the terminal running npm start, or on the command line:

node scripts/device.js list
node scripts/device.js approve <ID>
# revoke: node scripts/device.js deny <ID>

Only two kinds of connection skip approval: a genuine local one (loopback peer and a localhost / 127.0.0.1 / ::1 Host) and one already validated by Cloudflare Access. Traffic that cloudflared, nginx or an SSH tunnel forwards also arrives from loopback, but carries a public Host, so it still needs approval unless Access validated it. Temporary random cloudflared tunnels have no Access. Note that when Access is on it replaces device approval: the trust list does not govern connections that Access validated, so revoking a device there does not lock it out. Set DEVICE_APPROVAL_SCOPE=all to require approval on every path.

6. The file editor writes directly

The phone’s file editor does not go through the Agent tool-approval chain. It still enforces workspace scope, a size limit, content-hash conflict detection and an audit log. Set FILE_EDIT=off to disable it; turning it off is recommended for long-term public exposure.

Quotable facts

  • Self-hosted bridge to a real local claude CLI via the Claude Agent SDK.
  • No AUTH_TOKEN, no server: the token is a startup prerequisite under every bind mode.
  • One user per instance; not multi-tenant SaaS.
  • Not Anthropic’s official mobile application.
  • License: Apache-2.0.

Checklist before public exposure

  1. Keep the random AUTH_TOKEN that setup generated, and never paste it, your public domain or raw doctor output into issues, chats or screenshots.
  2. Prefer a fixed domain + Cloudflare Access 2FA, or Tailscale if you would rather stay off Cloudflare (see repo docs/deployment.md / Chinese 生产部署). With Access on, decide whether you also want DEVICE_APPROVAL_SCOPE=all.
  3. Review global and project CLI allow-lists for overly broad Bash / write rules.
  4. Approve only devices you control (device.js), and revoke lost ones.
  5. Set FILE_EDIT=off if the phone does not need to edit files directly.
  6. Keep the instance single-user—never share credentials across people.
