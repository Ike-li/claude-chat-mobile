# runbooks —— D / E 档的操作手册（按需建）

runbook 是**按功能域写的操作手册**，给 D 档（agent 判断）和 E 档（人用真机）用。
它装的是比 `check.how` 一两句长、又被同一个域里好几条用例共用的东西。没有它，下一轮的 agent
会把同样的坑再踩一遍——首轮验收里相当一部分时间花在现场重新摸这些门道上，几次误判也出在这里。

**按需建，不预建 24 份。** 只给「有 D/E 档用例、而且准备工作不简单」的域建，文件名
`dNN-<slug>.md`，与 `cases/` 里的用例文件同名。E 档的真机清单单独一份 `e4-device.md`。
用例的 `check.how` 里写一句「见 runbooks/dNN-<slug>.md」指过来。

## 首轮已知、建 runbook 时要写进去的

| 域 | 要写进去的 |
|---|---|
| D09 审批 | 测审批 TTL 要把 `APPROVAL_TTL_MS` 调小再重启服务 |
| D12 终端镜像 | 容器里起不了交互式 claude，只能用 stream-json 驱动；stream-json 不进会话注册表，也没有 /rewind |
| D13 断网 | 用 `docker pause`：约 30 秒才出断线横幅，`unpause` 后约 8 秒重连 |
| D18 推送 | ntfy 截获端的日志跨重启累积，必须按本轮时间过滤（首轮「重复推送」的误判就是这么来的） |
| presence 类 | 内置浏览器切标签模拟不了切后台，只能用真机或容器里的辅助客户端 |

## 模板

```markdown
# dNN <域名> —— 操作手册

适用用例：AC-NN-01、AC-NN-04 …（这些用例的 check.how 指向本文）

## 前置环境怎么造
- 要起哪些环境（env/up.mjs --env …），要不要改环境变量、重启哪个服务
- 种子数据怎么造（哪条命令、在哪个容器里）

## 共用的观察手段
- 看什么、在哪看：DOM 选择器 / 截图检查点 / docker logs 过滤方式 / 容器里查哪个文件
- 每种手段对应 lib/evidence.mjs 里的哪种证据

## 已知的坑
- 现象 → 原因 → 绕法（带日期，便于判断是否已过时）

## 证据要求
- 判 pass 至少要哪种外部可观察证据；哪些情况只能判 partial / blocked
```
