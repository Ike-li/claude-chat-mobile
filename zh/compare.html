诚实的对比

官方 Remote Control，还是自托管？

先说结论：大多数人应该直接用官方的 Claude Code Remote Control。它随 Claude 订阅附带，一条命令就能开，不用自己跑服务，也不用操心安全。这一页只讲它用不了的那几种情况，那才是自托管本项目这类工具的理由。如果你正好命中其中一条，后半部分再比较几种自托管方案，包括本项目。

关于 Remote Control 的事实取自 Claude Code 官方文档；其他项目的事实取自它们各自的 README 和文档，出处就近给出 · 核对于 2026-09-24

下表没有一条符合你的情况，就用官方 Remote Control 在任意 Claude Code 会话里运行 /remote-control，用 Claude App 扫一下二维码就行。不用装任何东西，不用开端口，也没有要你自己打补丁的服务器。它能用的话就是更好的选择，本项目没有什么可补充的。

官方 Remote Control 用不了的情况

下面是 Anthropic 官方文档里写明的硬性要求，不是观点。你的配置只要符合其中一行，Remote Control 就用不了，自托管的桥接工具是剩下为数不多的选择之一。

你的配置官方文档怎么说
用 API key 认证 原文「API keys are not supported.」Remote Control 要求用 claude.ai 账号登录，套餐为 Pro、Max、Team 或 Enterprise。
把 ANTHROPIC_BASE_URL 指向中转、第三方网关或代理（包括接国产模型的兼容端点） 变量指向「api.anthropic.com 以外的主机，例如 LLM 网关或代理」时不可用。（CLI v2.1.196 之前允许，此后收紧。）
跑在 Amazon Bedrock、Google Cloud 的 Agent Platform 或 Microsoft Foundry 上 官方明确列为不可用的 API 端点配置。
通过企业版 Claude apps gateway 登录 和上面几种列在一起，同属不可用的 API 端点配置。
设置了 DISABLE_TELEMETRY、DO_NOT_TRACK、CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC 或 DISABLE_GROWTHBOOK 任意一个都会关掉 Remote Control 所依赖的功能开关评估，要用 Remote Control 必须先取消设置。
组织要求零数据保留（Zero Data Retention） 原文「Organizations with compliance requirements such as Zero Data Retention can’t enable Remote Control.」

会话记录存在哪

这是另一处真正的区别，而且各有利弊。

  • 官方 Remote Control：连接期间，会话记录（你的消息、Claude 的回复和工具调用）存放在 Anthropic 的服务器上，这样才能在多台设备间同步，网络断了也能接上。代码执行和文件访问仍在你的电脑上。
  • 本项目：会话记录就留在 CLI 本来就会写的那些本地文件里，不在电脑以外存任何东西。代价是跨设备同步和断线重连要靠你自己的服务来做，而不是 Anthropic。

哪些不是区别

两种方式都得让电脑开着 两者驱动的都是你电脑上的 claude 进程。电脑休眠或进程退出，会话就离线了。自托管换不来一个不依赖你电脑的会话，如果你要的是那个，这两种都不对。

自托管要自己承担什么

直说，因为对比页通常会略过这一段：

  • 你要自己运行和更新一个 Node 服务，并决定手机怎么连到它：局域网、隧道，还是 Cloudflare Access。项目默认上锁，没有令牌就拒绝启动，但暴露到哪一步由你决定。
  • 一个实例只服务一个用户。没有多租户，也不打算做。
  • 推送通知要用你自己的 Web Push 密钥或 ntfy 主题，背后没有托管服务。
  • 没有官方手机 App，它是一个加到主屏幕的 PWA。

自托管方案怎么选

这个领域不只有本项目，它也不是最大的那个。下面几种方案的区别主要不在功能（功能每周都在变），而在形态：手机上用什么、手机怎么连到你的电脑、电脑上要跑什么。本节只讲这几点，因为它们很少变。各家当前有哪些功能，请看它们自己的 README。

如果你想要…选理由
原生手机 App，不用配置端口或隧道 Happy 手机和电脑都主动连到一台中继服务器，所有内容在离开电脑前就做了端到端加密。中继可以自己搭。
完整的浏览器工作台（终端、文件树、git），而且也用 Cursor CLI 或 Codex CloudCLI 由你电脑上的服务提供网页界面，有对话、终端、文件和 git 视图；同一网络下手机用 IP 加端口打开。
电脑上不装任何新东西，你本来就习惯终端 SSH + tmux 手机上一个 SSH 客户端，加一张 Tailscale 这样的私有网络，再在 tmux 里跑原生的 claude。
以手机为先、跟着终端走的界面（审批、AskUserQuestion、后台任务、你在终端里开着的那个会话），控制面留在自己电脑上 本项目 你电脑上的服务通过 Agent SDK 驱动本机的 claude CLI；服务、会话记录、设备信任和审计日志都留在那台电脑上。

Happy

有 iOS、Android 原生 App 和网页版，支持 Claude Code 和 Codex。电脑上安装 happy CLI，之后用 happy 代替 claude 启动会话。CLI 在内容离开电脑前先加密，由中继服务器把加密后的消息转给手机，中继本身读不了内容。因为两端都是主动连出去，所以不用设置端口转发。中继开源，可以自己部署。出处：README、How it works、Self-hosting。

CloudCLI（claudecodeui）

面向 Claude Code、Cursor CLI 和 Codex 的桌面与手机网页界面，带对话、内置终端、文件浏览器和 git 浏览器。自托管时它作为 Node 服务跑在你的电脑上，会自动发现你已有的会话。同一网络下手机打开 http://[你的电脑 IP]:3001，页面可以加到主屏幕。从外面访问时，它的文档建议前面放一个带认证的反向代理，临时用可以走隧道。另有付费的托管版 CloudCLI Cloud，agent 跑在云上。出处：README、Access from mobile、Remote server。

SSH + tmux，不装额外软件

继续用终端，只是换到手机上。安卓用 Termux；iOS 用 Blink 或 Prompt 这类 SSH 客户端。Tailscale 让手机有一条到你电脑的私有线路，网络不稳时 mosh 更好用，tmux 让 claude 会话在两次连接之间一直跑着。出处：How I Use Claude Code on My Phone with Termux and Tailscale。

Claude Chat Mobile（本项目）

以手机为先的网页界面，可以作为 PWA 装到主屏幕，目标是和终端对齐：工具审批、AskUserQuestion、后台任务，以及你在终端里开着的那个会话，同一时刻只有一个驾驶端。服务跑在你的电脑上，通过 Agent SDK 驱动本机的 claude CLI，所以那个 CLI 配的是哪家模型通路，它就用哪家。可以走局域网，也可以走你自己选的隧道、VPN 或反向代理；没有令牌就拒绝启动，新的远程设备要先审批一次，除非前面有 Cloudflare Access 这样的身份层。出处：README、安全模型。

常见问题

该用 Claude Chat Mobile 还是官方的 Claude Code Remote Control？

大多数人用官方 Remote Control。Pro、Max、Team 或 Enterprise 套餐都带它，一条命令就能用，不用自己跑服务，也不用操心安全。Claude Chat Mobile 是给 Remote Control 用不了的情况准备的：用 API key 认证、通过 ANTHROPIC_BASE_URL 接了第三方网关或代理、跑在 Bedrock / Google Cloud Agent Platform / Microsoft Foundry 上，或者会话记录不能离开你的电脑。

Claude Code Remote Control 支持 API key 或第三方网关吗？

不支持。官方文档写明不支持 API key；ANTHROPIC_BASE_URL 指向 api.anthropic.com 以外的主机（例如 LLM 网关或代理）时，Remote Control 也不可用。Claude Chat Mobile 直接驱动你本机的 CLI，那个 CLI 配的是哪家，它就用哪家。

我的会话记录存在哪？

用官方 Remote Control 时，连接期间会话记录存放在 Anthropic 的服务器上，以便在多台设备间同步。用 Claude Chat Mobile 时，会话记录留在你自己的电脑上，就是本机 CLI 本来就会写的那些文件。

电脑需要一直开着吗？

两种都需要。两者驱动的都是你电脑上的 claude 进程，电脑休眠或进程退出，会话就离线了。自托管改变不了这一点。

Happy、CloudCLI 和 Claude Chat Mobile，自托管该选哪个？

它们解决的是同一个问题，只是形态不同。Happy 提供 iOS 和 Android 原生 App，网络由一台端到端加密的中继服务器解决，中继也可以自己搭。CloudCLI 是带对话、终端、文件和 git 视图的浏览器工作台，还能驱动 Cursor CLI 和 Codex，手机通过你的网络或你自己配置的代理访问它。Claude Chat Mobile 是以手机为先的网页界面，尽可能贴近你本机的 claude CLI，服务、会话记录和设备信任都在你自己的电脑上。如果官方 Remote Control 在你的配置下能用，先用它。
